# Devlog — v1.0.x Bugfixes

The first audit of Lumen (2026-09-22) found the bugs below. Each shipped as its own patch tag,
ordered by user impact: data loss first, then broken flows, crashes, and edge cases. `v1.0.0` and
`v1.0.1` predate the audit.

| Tag | Fix |
|---|---|
| `v1.0.2` | Switching build no longer wipes the game's config: `setSelectedBuild` uses `copyWith`, and switching the build of an installed game confirms first, then repairs against the new build. |
| `v1.0.3` | Re-running Import after a failed or completed Import works: `startVerification` dequeues the old task and clears the cached verification stream first, as `startDownload` already did. |
| `v1.0.4` | Saves tab progress updates live. A stopgap (watch the whole `savesStateProvider`), replaced by immutable tasks in `v1.1.0`. |
| `v1.0.5` | A download with allocation errors is no longer marked installed: its `onDone` checks `errorFiles`, as repair does. |
| `v1.0.6` | The library shows error and empty states with a Retry instead of spinning forever. Relies on `gogdl_flutter` `v1.1.3`, which filters `getOwnedGames()` to real games; that filtering is one lookup per product, unordered and uncached, so a lookup failure can make the list `[]` — hence Retry on the empty state too. |
| `v1.0.7` | The Builds tab no longer crashes when fetching builds fails. |
| `v1.0.8` | No `setState` after dispose in the login, Overview, DLC and Library `initState` flows (`mounted` checked after every `await`), and the login `TextEditingController` is disposed. |
| `v1.0.9` | Login catches non-`GogError` failures: a missing stored token isn't an error, and anything else (e.g. no keyring) shows a snackbar. |
| `v1.0.10` | Debug and release builds follow the same error contract: `GogState`'s image, summary and screenshot getters log and return `''`/`[]` in both. |
| `v1.0.11` | Hero banners stop refetching and flickering: background links are cached per game like boxart. |
| `v1.0.12` | Removing a Proton version clears the per-game overrides pinned to it. |
| `v1.0.13` | A Proton download that closes without a `Finished` event is marked failed, not installed. |
| `v1.0.14` | Syncing saves before the first launch stops with a "launch the game once" message and creates no prefix dir (the suspected skipped-prefix-init bug didn't reproduce). |
