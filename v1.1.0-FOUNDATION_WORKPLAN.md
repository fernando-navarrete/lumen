# v1.1.0 — Foundation work plan

The work plan for the `v1.1.0` entry in [ROADMAP.md](ROADMAP.md): tests, CI and the state
architecture. The follow-up `v1.1.x` patches build on it. Each phase below should fit in one
short session and end with a green `fvm flutter analyze` (and `fvm flutter test` once `test/`
exists) plus one commit. The tag is cut only at the end (Phase 9), so `main` keeps shipping as
`1.0.14` until then.

Tick each checkbox as it's done. If a phase turns out bigger than one session, split it here
before starting, not halfway through.

## Scope

From ROADMAP `v1.1.0`, with the GAPS reference for each:

| # | Item | GAPS | Phase |
|---|---|---|---|
| A | `gogBackendProvider` so tests can swap in a fake `GogBackend` | §4 P1 | 1 |
| B | Resolve the `lib/models/` mismatch between CLAUDE.md and the code | §4 P1 | 2 |
| C | `test/` covering the notifiers, `guardBridgeStream` and `findExecutables`, plus 1.0.x regression tests | §7 P0 | 1, 3, 4, 8 |
| D | Immutable `ActivityTask`, `SaveTask`, `ProtonTask`, `RunningGame`, replacing the `v1.0.4` stopgap | §4 P1 (4.1) | 5, 6 |
| E | Nav state as a single `Notifier<NavBarItem>` | §4 P1 | 7 |
| F | CI (GitLab CI, self-hosted runner on `thinkcentre.home`) running analyze and test | §7 P1 (×2) | 0, 8 |

**Out of scope:** everything in the `v1.1.1+` patch list (stream caches, error-handling
consistency, emit throttling, settings debounce, schema version, secure storage). Where a phase
touches that code, leave it alone and note what you found under that patch in ROADMAP instead.

## Ordering rationale

- The backend seam and test harness (Phase 1) come first because every later phase adds tests
  through them.
- The models decision (Phase 2) goes before the notifier tests, so the fake backend and fixtures
  are written once against the final types.
- Characterization tests for the notifiers (Phases 3–4) go **before** the immutability refactor
  (Phases 5–6), so the refactor has a safety net. The tests only read `state`, so they pass
  against both the mutable and the immutable implementation.
- Phase 0 (making `gogdl_flutter` reachable) is infrastructure that may depend on external
  accounts. It can run in parallel with anything else, but CI (Phase 8) is blocked on it.

## Phase 2 — Resolve the `lib/models/` mismatch

CLAUDE.md says `GameBuild`, `DownloadableProduct` and `ProtonRelease` are app-owned classes under
`lib/models/`, but that directory doesn't exist and `GogBackend` returns the bridge's types.

**Recommended: add the models** (not just fix the docs). The goal of this release is a testable
seam, and `GameBuild.releaseDateTimestamp` is a bridge `PlatformInt64` and
`ProtonRelease.downloadSize` a `BigInt`, which leak bridge details into the UI and the fakes.

- [x] Create `lib/models/game_build.dart`, `downloadable_product.dart` and `proton_release.dart` as
  plain immutable classes with `==`/`hashCode`. Use app-friendly types: `DateTime` or `int` for the
  timestamp, and `int` for `downloadSize` (then check whether `formatBytesBigint` still has any
  callers; merging the two helpers stays in `v1.5.2`). Kept `releaseDateTimestamp` as `int` (only
  ever compared, never displayed) rather than `DateTime`. `formatBytesBigint` has no callers left;
  noted in ROADMAP `v1.5.2` that it's now a straight deletion.
- [x] Change `GogBackend` to return the app types, and have `GogdlBackend` adapt the bridge types.
  Import the bridge's types with a prefix or `hide` so the names don't clash. Used `hide GameBuild,
  DownloadableProduct, ProtonRelease` plus a second `as bridge show` import in `gogdl_backend.dart`
  for the three private adapters (`_adaptBuild`, `_adaptProduct`, `_adaptRelease`).
- [x] Update the call sites: `game_action_buttons.dart`, `builds_tab.dart`, `products_tab.dart`,
  `proton_manager.dart` and `proton_state.dart`. The four UI files dropped their `gogdl_flutter`
  import entirely (they only needed it for these models); `proton_manager.dart` also switched its
  one `formatBytesBigint` call to `formatBytes`.
- [x] Update `FakeGogBackend` to use the app models.
- [x] Leave the six progress unions as bridge types (CLAUDE.md already documents that exception).
- [x] Update the CLAUDE.md wording if anything changed from what it already describes. No change
  needed — CLAUDE.md already described this target state.

**Alternative, if you'd rather not add models:** correct CLAUDE.md to say `GogBackend` returns
bridge types, and delete the "app-owned" paragraph. This is a 10-minute phase.

**Done when:** `grep -r "lib/models" CLAUDE.md` matches reality, and analyze passes.

## Phase 4 — Characterization tests for the stream-owning notifiers

Script events through `FakeGogBackend`'s controllers and assert on `container.read(xStateProvider)`.
Build progress events with the bridge's freezed constructors. These tests are the safety net for
Phases 5–6, so assert only on *values* read from state, never on object identity.

Split this across two sessions if needed (4a, then 4b).

**4a — `DownloadsNotifier`** (`test/state/downloads_state_test.dart`)
- [ ] Download: stage transitions, file-counted → byte-counted progress, and `Finished` → the game
  is marked installed.
- [ ] Regression `v1.0.5`: a download that finishes with allocation `errorFiles` is **not** marked
  installed.
- [ ] Verification: missing/corrupt/unreadable events fill `verifyFailures`, and `errorFiles` is
  derived from them.
- [ ] Regression `v1.0.3`: re-running Import after a failed Import dequeues the old task and
  starts a fresh stream (check the fake's call log).
- [ ] Repair: damaged files stay in `verifyFailures`, and `errorFiles` holds only allocation errors.
- [ ] A late stream error (from `guardBridgeStream`) marks the task failed.

**4b — `SavesNotifier`, `ProtonNotifier`, `LaunchNotifier`**
- [ ] Saves (`saves_state_test.dart`): download byte progress vs. upload file progress,
  `SaveTask.isEmpty` on a zero-file finish, and an error sets `error`/`failed`.
- [ ] Regression `v1.0.14`: syncing a game whose prefix has no `pfx` fails early with the
  "launch the game once" message and creates no directory. Use a temp `XDG_DATA_HOME`; if
  `app_paths.dart` can't be pointed at one, add a small override seam there.
- [ ] Regression: a finished stream is cleared before a re-run, so a second sync works.
- [ ] Proton (`proton_state_test.dart`): `Finished` → installed with the reported path, and
  persisted.
- [ ] Regression `v1.0.13`: a stream closed without `Finished` → failed, not installed.
- [ ] Regression `v1.0.12`: `removeVersion` clears per-game overrides pointing at it.
- [ ] Launch: `RunningGame` status transitions only if they can be tested without spawning Proton.
  Otherwise skip, and note it for `v1.2.0` (where process handling changes anyway).

**Done when:** every notifier that owns a stream has event→state tests, and each 1.0.x regression
that lives in a notifier has a test named after its tag.

## Phase 5 — Immutable `ActivityTask` (the big one)

`downloads_state.dart` has about 48 in-place field writes on tasks. Do this phase on its own.

- [ ] Make every field of `ActivityTask` `final`, and add `copyWith`, using the same `_unset`

  `buildName`).
- [ ] Make collection fields unmodifiable (`List.unmodifiable` / `Map.unmodifiable`) in the
  constructor or `copyWith`, so an accidental in-place write fails fast.
- [ ] In `DownloadsNotifier`, replace each `task.x = …` with building a new task and

- [ ] Check the throttle's last pending update always flushes on `onDone`/error.
- [ ] Add an identity test: after an event, `state.tasks[id]` is a new object, and the old
  snapshot still has its old values.

- [ ] Manually check the Downloads page during a real download, verification and repair.

**Done when:** `grep -nE "task\.[a-zA-Z]+ *=[^=]" lib/state/downloads_state.dart` finds nothing,
