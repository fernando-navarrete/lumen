# Devlog — v1.5.0 UI polish and packaging

A login screen that doesn't flash, guess or overflow, a proper window (minimum size, icon), one
breakpoint helper for the detail tabs, keyboard focus and semantics for `ClickableContainer`,
adoption of the bridge's breaking `v1.5.0` cleanup, and an AppImage built and published by a release
pipeline — the `v1.5.0` ROADMAP entry — plus the `v1.5.1`–`v1.5.2` patches. Ran as phases 0–10 and two
patches over 2026-10-13 to 2026-10-17, with Phase 6 done in the dependency repos. Kept here for the
decisions and pitfalls that aren't obvious from the diff. Ended at 506 passing tests and
`flutter analyze --fatal-infos` clean (baseline 450).

There was no long-lived release branch; `main` is protected, so each group of phases was its own MR.
SHAs are the merge commits on `main`: Phases 0–5 `e5027b8`, Phase 7 `e10bead`, Phases 8–9 `aa86240`,
the `-r5` CI image `1c4fdc0`, Phase 10 `f7de4b1` (tagged `v1.5.0`), the tag-result note `b2c02a9`, then
one MR per patch: `8407ea4` (`v1.5.1`) and `f29854a` (`v1.5.2`). The work plan was deleted with this
devlog.

## Phase 0 — Investigation

**Login failures** (gogdl-lib `v1.3.2`, bridge `v1.4.3`, real GOG). A bad or truncated code and an
expired one are both `400 invalid_grant`, told apart only by `error_description`, so one
`invalidLoginCode` kind is enough. GOG accepted the same code twice, so "reused" isn't a failure. A
network failure on login was flattened by `AuthManager::exchange` into a string and fell through to
`GogErrorKind.unknown`, same as a bad code, so the bridge also had to map login to `network`.

**AppImage.** glibc floor 2.34 (runs on Ubuntu 22.04 and 24.04). GTK 3 and libsecret come from the
host; the bundle is 37 MB, the AppImage 14 MB. Without a system CA bundle the bridge panics (`reqwest`
loads no certificates). Hosts with AppImageLauncher's binfmt handler hang unless
`APPIMAGELAUNCHER_DISABLE=1`. `appimagetool` reports itself as "continuous build 296", so it is pinned
by sha256, not version.

**Env leak.** The runtime adds exactly `APPDIR`, `APPIMAGE`, `ARGV0` and `OWD`; `PATH`,
`LD_LIBRARY_PATH` and `XDG_DATA_DIRS` are untouched. Proton, `wineserver`, `wineboot` and
`services.exe` all inherited them.

**Flatpak, stopped.** `org.freedesktop.Platform` has neither GTK 3 nor libsecret, so the app dies at
startup; `org.gnome.Platform` is 408 MB to download. Secret Service, portal paths and Proton in the
sandbox were never tested. Decision: AppImage only, so no precompiled `.so` (D2) either.

**Build traps.** The CI image lacked `libsecret-1-dev`, so `flutter build linux` failed in it. A failed
configure also leaves `CMAKE_INSTALL_PREFIX=/usr/local` in the CMake cache, so retries install outside
`bundle/`; the script builds from a clean `build/linux`.

## Phase 1 — Window

960×600 minimum via `gtk_window_set_geometry_hints`, and an icon from the `GlowingSquare` mark (SVG
plus hicolor PNGs). The application ID moved to `io.github.fernando_navarrete.Lumen` (AppStream IDs
can't have `-` there; the old one didn't match the GitHub account). **Trap:** the ID names the
SharedPreferences directory and the keyring schema, so renaming it silently signs everyone out and
drops their settings. `migrateLegacyPreferences()` copies the prefs file (the old one stays for
downgrade); the keyring token is not carried over.

## Phase 2 — Breakpoints

`sideColumnWidth` replaced three `pow(width * 0.05, …)` curves with fixed widths (0 below 600, 280 to
1200, 340 above), measured on the tab by a `LayoutBuilder` in `SideColumnLayout`. Visible changes:
Overview now shows its facts column at the 960 minimum, 280 at 1280 (was 223), 340 at 1920 (was 377).

## Phase 3 — `ClickableContainer`

Now a `FocusableActionDetector` with button `Semantics`, a 2px `AppColors.primary` ring on keyboard
focus only, and an optional `semanticLabel` (only the icon-only remove button needed one). List rows
in Builds and DLC moved their padding outside so the ring hugs the panel. A disabled one isn't
focusable, but its semantics node still reports `isFocusable`.

## Phase 4 — Deprecated getters

One `GameLinks` Future per game feeds both boxart and background (the derived Futures are
`getBoxartLink`/`getBackgroundLink`, renamed so they don't echo the removed bridge names).
`protonReleasesProvider` yields a `ProtonReleasePage`; the dialog ends on `hasMore == false`, so a
fully filtered page no longer looks like the end.

## Phase 5 — Login screen

Restore shows a `CenteredLoader` immediately with no delay: it is only a keyring read and a JSON
parse, no network call. Steps advance on app resume, focusing the code field and typing, never a timer.
`extractLoginCode` accepts a pasted redirect URL. Errors are inline, keyring failures included. The
branding pane hides below `Breakpoints.loginSplit` (760), which is 896 wide at the minimum size, so
both panes still show there. `LoginScreen` finally has widget tests.

## Phase 6 — Dependency work

Already shipped when reached, so checked rather than redone: gogdl-lib `v1.4.0` (`AuthError` split into
`InvalidLoginCode`, `SessionRevoked`, `NetworkError`, `Rejected`, `InvalidResponse`) and `gogdl_flutter`
`v1.5.0` (`c9fc04c`: the new error kinds and the breaking cleanup). The Rust pin stayed 1.98.1, so no
CI image bump for the bridge. The `lumen-cli` bump was skipped by gogdl-lib's own decision.

## Phase 7 — Adopt the bridge

Named fields replaced every `field0`/`field1`. `GameBuild` kept only the timestamp; the Builds tab
formats it with `formatReleaseDate` (UTC `yyyy-MM-dd`, no `intl`), which removed the `+0000` hack.
`ProductType { game, dlc, other }` is app-owned. `loginErrorText` reads `invalidLoginCode` as a bad
code; `jobErrorText`'s exhaustive switch routes the new kind to `message()`.

## Phase 8 — Packaging

`tool/build_appimage.sh` builds clean, assembles the AppDir and runs the pinned `appimagetool` with the
pinned type2 runtime. `hostEnvironment()` drops the four runtime vars only when `APPIMAGE` is set, and
every spawn passes it with `includeParentEnvironment: false`. **Decision:** "Open log" and the login
URL went through `url_launcher`, which opens in-process via GIO with no control over the environment,
so both moved to `openExternallyProvider` (`xdg-open`) and `url_launcher` left `pubspec.yaml`.

## Phase 9 — Release pipeline

`CHANGELOG.md` plus `tool/release_notes.sh` (tag format, `pubspec.yaml` version equals the tag,
non-empty section), and the `package`, `publish` and `release` jobs. `libsecret-1-dev` went into the
CI image (`-r4`, then `-r5` for `file(1)`, which `appimagetool` needs), so Lumen's pipeline was red
until the image was rebuilt on thinkcentre.home. The `package` job was run manually on its MR first.

## Phase 10 — Release

README's "Installing" is build-it-yourself, since there is no public download channel. The `v1.5.0`
tag pipeline was green, including `check_bridge_pin.sh`'s first tag run, and the GitLab release has
the AppImage attached.

## Patches

**`v1.5.1`: the summary is plain text.** Sampled 27 gamesdb records (the 7 local games plus 20
catalog titles): the `en-US` summary is plain text for every `type: game` record. HTML only appears
in `type: spam` records, which gogdl-lib rejects. So no converter, one widget test pins verbatim
display.

**`v1.5.2`: one `formatBytes`.** The ROADMAP was wrong that `formatBytesBigint` had no callers:
`jobErrorText` used it for `SpaceShortfall`'s `BigInt`s. It is merged with `.toInt()`, and the
not-enough-space test now pins the exact string. The stale `buildId` comment is gone.

Both tag pipelines were green and both GitLab releases exist.
