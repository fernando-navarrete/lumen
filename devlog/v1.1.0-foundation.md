# Devlog — v1.1.0 Foundation

Tests, CI and the state-architecture cleanup from the `v1.1.0` ROADMAP entry. Ran as nine phases
over 2026-09-22/23; kept here for the decisions and pitfalls that aren't obvious from the diff.
Ended at 102 passing tests, `flutter analyze --fatal-infos` clean, and green GitLab CI.

## Phase 0 — Making `gogdl_flutter` reachable
Chose to keep everything LAN-only (a self-hosted GitLab runner on `thinkcentre.home`) rather than
mirror to a public forge — covers "reachable by CI", not "reachable by other contributors"
(deliberately deferred). Confirmed `flutter test` needs no Rust toolchain: the native lib is only
`dlopen`'d inside `RustLib.init()`, which the fake backend never calls.

## Phase 1 — `gogBackendProvider` and the test harness
Added `gogBackendProvider` (owns the `GogdlBackend`/dispose) with `gogStateProvider` watching it,
plus `FakeGogBackend` and `createContainer()` test helpers.

## Phase 2 — `lib/models/`
Added `GameBuild`/`DownloadableProduct`/`ProtonRelease` as plain app-owned classes (app-friendly
`int` types instead of the bridge's `PlatformInt64`/`BigInt`), with `GogdlBackend` adapting the
bridge's own types into them. Left `formatBytesBigint` with no callers (tracked as a straight
deletion in `v1.5.2`).

## Phase 3 — Pure-unit tests
`guardBridgeStream`, `findExecutables`, `GamesNotifier`, `formatBytes`. **Pitfall:** `fake_async`
can't reliably drive `guardBridgeStream`'s grace-period timer — its `onCancel` returns the inner
subscription's `cancel()` future, which doesn't resolve in fake time. Used real `Future.delayed`
waits instead (grace period is only 250ms).

## Phase 4 — Characterization tests for the stream-owning notifiers
Covered `DownloadsNotifier`, `SavesNotifier`, `ProtonNotifier`, `LaunchNotifier` before the
immutability refactor, asserting only on state values (never object identity) so the tests would
survive both the mutable and immutable implementations. Added `app_paths.dart`'s
`xdgDataHomeOverride` test seam (`test/helpers/temp_data_home.dart`) so Proton-prefix tests never
touch the real `lumenDataDir()`. `LaunchNotifier` tests point `protonPath` at a fake `proton` shell
script instead of spawning real Proton. Characterized (didn't fix) a real gap: a `finished` event
followed by a late stream error still lets `onDone` re-derive `completed` — tracked as `v1.1.2`.

## Phase 5 — Immutable `ActivityTask`
Made every field `final` with `copyWith` (`_unset` sentinel) and unmodifiable collections. Found a
latent bug while doing this: a stream whose task had been dequeued/replaced could still clobber the
task that replaced it once updates went through `copyWith` instead of in-place mutation. Fixed with
a stale-stream guard in `_commit` (only writes `next` if `current` is still `identical` to the task
registered for that gameId) — side effects like `markInstalled` stay unconditional, matching prior
behavior.

## Phase 6 — Immutable `SaveTask`, `ProtonTask`, `RunningGame`
Same pattern, one `_commit` per notifier (no throttling needed — only `DownloadsNotifier` throttles
emits). Removed the `v1.0.4` Saves-tab stopgap now that tasks are real new objects on every event.
Found the launch-failure snackbar (`game_action_buttons.dart`) was dead code before this: its
`ref.listen` compared `previous`/`next` off the same mutated `RunningGame` instance, so the guard
was never true. It fires correctly now.

## Phase 7 — Nav state
Replaced the mutable `NavBarState`/plain `Provider` + `NavBar`'s own `_selectedItem` with a single
`NavBarNotifier extends Notifier<NavBarItem>`.

## Phase 8 — CI
No `ghcr.io/cirruslabs/flutter:3.47.2` image exists (newest tag is `3.44.0`), so the job clones
Flutter itself at the `.fvmrc`-pinned tag into a cached `.ci/flutter/`. `gogdl_flutter` access uses
a base64-encoded SSH deploy key (`GOGDL_DEPLOY_KEY_B64`) — GitLab's "File" variable type mangled the
raw multi-line PEM on paste. **Pitfall:** the key was marked "Protect variable", so it came through
empty on the unprotected branch used to test CI-red, failing at `ssh-add` instead of at the test —
unchecked it (read-only key, still masked; CI needs to run on every branch). If a job can't resolve
`thinkcentre.home`, the runner's Docker containers aren't seeing the LAN `/etc/hosts` entry — fix
via `extra_hosts` in `/etc/gitlab-runner/config.toml`.

Added `test/flutter_test_config.dart` (stubs `google_fonts`' runtime fetch) and
`test/helpers/pump_app.dart` to unblock widget tests. Could not add a widget test for `v1.0.9`
(login): `LoginScreen`'s outer `Container` uses `EdgeInsets.all(size.width * 0.1)`, so a
wide-but-short surface's width-derived margin also eats vertical space, and separately
`SignInPanel`'s "Open GOG login" button overflows its row once the Onest font isn't loaded —
reproduced at multiple surface sizes, so it's a real layout bug, not a test-harness limitation.
Filed under GAPS §6.

Confirmed CI actually goes red with a throwaway failing test on a scratch branch, then deleted it.
